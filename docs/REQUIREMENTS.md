# portwatch 요구사항

문서 기준: 2026-11-18. 로컬 개발 서버를 한곳에서 보고 멈추는 macOS 메뉴바 앱이다.
이 프로젝트는 문서 기반 개발(Doc-Driven Development, DDD)로 진행한다.

[설계](./DESIGN.md) · [구현 계획](./IMPLEMENT.md) · [수동 검증](./MANUAL_TEST_CHECKLIST.md)

## 목적과 사용 맥락

회사 Mac에서 개발할 때 로컬 서버가 여러 방식으로 동시에 떠 있다.

- 포트만 다른 localhost 서버 여러 개(`npm run dev` 등)
- hosts 파일로 도메인을 연결하고 인증서를 붙인 서버
- Homebrew로 설치해 `brew services start`로 띄운 Jenkins·nginx 같은 서비스
- `sudo brew services start`처럼 root 권한으로 띄운 서비스

사용자 설명(2026-11-18): 실행 방식이 "천차만별이라 애매"하다. 이런 서버를 모두 모아서 보여주고,
선택해서 프로세스를 멈출 수 있으면 회사에서 쓰기 편리하다.

## 기존 도구 검토 (2026-11-18)

만들기 전에 비슷한 도구를 조사했다. 세부 근거는 각 프로젝트의 README와 소개 페이지다.

| 도구 | 사용자 규모·유지보수 | 이 프로젝트와의 차이 |
| --- | --- | --- |
| LeftOpen | GitHub 스타 147, 최근 석 달 커밋 104 | 프로젝트별 묶기와 `brew services stop`을 지원한다. 사용자가 회사 Mac에서 직접 시험했고 root로 띄운 서비스는 잡지 못했다. |
| PortKiller | GitHub 스타 약 5,200, 최근 석 달 커밋 11 | 포트 보기와 종료 중심이다. 프로젝트 묶기·brew 서비스·root 처리 언급이 없다. |
| Raycast Port Manager | 설치 약 66,000 | 현재 사용자 권한으로만 동작한다. sudo 기능을 일부러 제거했다. |

세 도구 모두 무료다. root로 띄운 서비스 처리와 기존 nginx 설정을 읽어 도메인을 연결하는 기능은 찾지 못했다.
이 두 가지가 이 프로젝트를 만드는 이유다.

## 요구사항의 상태

- **확인됨**: 사용자가 직접 요청했거나 선택한 내용.
- **설계 제안**: 기본 동작을 구체화한 초안. 사용자 확인 사항과 혼동하지 않는다.
- **구현됨**: 실제 코드와 검증 근거가 있는 상태. 현재 구현된 항목은 없다.
- 세부 결정은 설계의 DC 체크리스트에서 관리한다. TBD를 임의로 확정된 것으로 표시하지 않는다.

## 확인된 사실: 사용자 Mac 관찰 (2026-11-18)

사용자가 회사 Mac에서 `sudo brew services start nginx`로 nginx를 root 서비스로 띄우고 sudo 없이 확인했다.
사용자 이름 같은 개인 정보는 기록하지 않는다. macOS 버전은 아직 기록하지 않았다(DC-03).

| 확인한 것 | 방법(sudo 없음) | 결과 |
| --- | --- | --- |
| root 프로세스의 포트 | `netstat -anv -p tcp` | `*.8080` 행에 PID가 나온다. root·`nobody`·launchd(1번) 소유 포트 모두 PID가 보인다. |
| 같은 포트를 lsof로 | `lsof -iTCP -sTCP:LISTEN -nP` | 8080이 나오지 않는다. 자기 프로세스의 포트만 보인다. |
| netstat 열 위치 | `netstat -anv -p tcp \| head -2` | 헤더에 `pid`·`epid` 열 이름이 있다. `Local Address`처럼 띄어쓰기가 있는 열 이름도 있다. |
| nginx 프로세스 구조 | `ps -axo pid,ppid,user,command` | master는 root, 부모 PID 1. worker는 `nobody`, 부모는 master. root 프로세스의 명령줄도 읽힌다. |
| 프로세스 이름 | 위와 같음 | nginx가 명령줄을 `nginx: master process …`로 바꿔 쓴다. |
| 서비스 라벨과 plist | `launchctl print system/sh.brew.nginx` | 라벨 `sh.brew.nginx`, plist `/Library/LaunchDaemons/sh.brew.nginx.plist`, `state = running`, `pid`, 실행 파일·인수·작업 폴더가 나온다. |
| PID → 라벨 표 | `launchctl print system` | 서비스 목록에 `PID  상태  라벨` 행이 나온다(예: nginx master PID와 `sh.brew.nginx`). |
| brew의 상태 표시 | `brew services list` | 실제로 실행 중인데 상태가 `none`, 사용자가 `root`로 나온다. |
| 포트를 연 프로세스 수 | netstat | 17개 중 개발 서버로 보이는 것은 node 하나와 nginx뿐이다. 나머지는 은행·인증 보안 프로그램, 엔드포인트 보안 에이전트, Kerberos(88), launchd가 직접 연 포트(22 등), 로컬 개발 도구의 임시 포트다. |

부수 효과: `sudo brew services start`는 nginx 실행 파일과 링크 4개의 소유자를 `root:admin`으로 바꾼다.
시험 뒤 `find /opt/homebrew -user root`로 확인하고 본인 소유로 되돌렸다. 수동 검증 준비 절에 같은 정리 절차를 둔다.

## 비목표

- Windows·Linux 지원(RQ-01). 핵심 로직의 Linux 테스트는 개발 편의일 뿐 지원 약속이 아니다.
- 서버 시작, 설정 편집. hosts·nginx·plist 파일은 읽기만 한다.
- 원격 서버, 포트 포워딩, 터널 관리.
- Mac App Store 배포. 다른 프로세스 정보를 읽고 멈춰야 해서 샌드박스 밖에서 실행한다.
- 앱 전체를 root로 실행하는 방식.

## 제약

- 탐지는 sudo 없이 한다. 관리자 권한은 사용자가 확인한 멈추기 동작 하나에만 쓴다.
- 테스트 자료는 관찰한 출력 형식을 바탕으로 만든 합성 자료다. 사용자 이름·사내 정보·실제 출력 원문을 저장소에 넣지 않는다.
- 저장소는 비공개(private)다. GitHub Actions의 macOS 실행 시간이 유료 한도에 포함될 수 있다(DC-10).
  Homebrew는 비공개 저장소의 Releases 파일을 인증 없이 받지 못한다(DC-18).
